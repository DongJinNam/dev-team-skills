# 작업 회의록 계약

작업을 맡긴 사람이 나중에 "어떻게 진행했고 왜 이렇게 했는가"를 다시 묻지 않아도 되게 남기는 기록이다. 작업 1건당 파일 1개를 작업 대상 repo의 `docs/worklogs/YYYY-MM-DD-<작업-slug>.md`에 둔다. 회의록은 새 기록 형식을 만들지 않는다. 시작·중단 합의, [결정 기록](./decision-governance.md), 검증 기록, 비용 기록처럼 이미 흩어져 있는 기록을 작업 단위로 묶는 색인이다.

## 1. 작성 시점과 책임

- 작업이 종료되거나 합의된 중단 조건으로 멈출 때 Tech Lead가 1회 작성한다. 중단된 작업도 남긴다.
- 역할별 행은 각 역할의 산출물과 인계 기록에서 옮긴다. 회의록에서 새 사실을 만들지 않으며, 확인되지 않은 것은 미확인으로 적는다.
- 활성화되지 않은 역할은 행을 만들지 않는다. 겸임은 겸임으로 표기한다.

## 2. 양식

맨 위의 요약은 [3문장 요약 계약](./report-summary.md)을 그대로 적용한다. 본문은 고정 필드만 쓰며, 사람 독자와 에이전트 파싱이 같은 표를 본다.

```markdown
# 작업 회의록: <작업명>

<무엇을·어떻게·왜 3문장>
판정: 완료 | 중단 | 미완료

## 메타
- 작업 ID/날짜:
- 요청 출처:
- 기준 리비전: base <sha> / head <sha>
- 시작·중단 합의: <기록 링크 또는 AGREED/PENDING>

## 역할별 기록
| 역할 | 실제 담당/겸임 | 한 일 | 왜 (근거·기각한 대안) | 산출물·증거 경로 | 상태 |
| --- | --- | --- | --- | --- | --- |
| Tech Lead |  |  |  |  | 완료/미실행/해당없음(근거) |

## 결정 색인
- <결정 기록 링크> — 본문을 복제하지 않는다

## 검증 요약
- AC -> 테스트 -> 실제 결과: <증거 경로>

## 비용
- 추가 호출·비용: 실측/추정/미확인을 구분해 Lead 기록을 연결한다

## 미해결·다음
- 미해결 사항:
- 다음 행동/담당:
- 재개·재판단 조건:
```

## 3. 작성 규칙

- 대화 전문과 긴 실행 로그를 붙이지 않는다. 증거는 경로로 링크한다. 회의록 자체가 컨텍스트 팽창 원인이 되면 안 된다.
- 결정·검증·비용의 본문은 원본 기록에 두고 회의록은 링크와 한 줄 요약만 둔다. 같은 사실을 두 곳에 쓰면 어긋난다.
- 상태 값은 완료/미실행/해당없음(근거)으로 구분한다. 미실행을 완료로 쓰지 않는다.
- 보안 판정과 컴플라이언스 상태는 원본 기록의 값을 그대로 옮긴다. 회의록이 판정을 바꾸지 않는다.

## 4. 크기 차등

| 관찰 조건 | 양식 |
| --- | --- |
| 문서·국소 수정, 외부 동작/신뢰 경계 불변 | 약식: 3문장 요약 + 판정 + 역할별 기록 표만, 10줄 이내 |
| 사용자 기능·API·에이전트 동작 변경, 제품·배포 변경 | 정식 양식 전체 |

차등 경계는 SKILL.md의 작업 크기별 활성화 표와 같다. 회의록 작성이 작업보다 커지면 약식으로 내린다.

## 5. 파일럿과 재판단

효과 실측은 아직 없다. 도입 후 실제 작업 3건에 적용해 아래를 기록하고 유지·축소·폐기를 재판단한다.

- 사용자가 회의록만으로 진행 경위와 결정 이유를 이해했는가 (재질문 발생 여부)
- 회의록 작성 비용 (줄 수와 Lead가 기록한 실측/추정 비용)
- 제3의 에이전트가 회의록만 읽고 미해결 사항과 재개 조건을 정확히 답할 수 있는가

이 파일럿은 기존 19개 압력 시나리오 점수에 넣지 않는다. 별도 보충 기록으로 남긴다.

## 6. 채택 근거와 한계

2026-11-11 확인: [에이전트 간 인계(HANDOFF.md) 관행](http://umatechnology.org/how-to-hand-off-a-coding-project-between-ai-coding-assistants-without-losing-context/)은 목표·완료/미완료 분리·결정과 증거·정확한 작업 상태·다음 행동을 필드로 둔다. [SYNTAX Methods Note v1.0](https://www.qntxlabs.com/research/syntax-methods-note-v1.0.pdf)의 세션 로그는 목표·행동·증거·수정·테스트·비용·미해결 위험을 담고 "대화 전문 덤프가 아닌 압축된 인계 기록"으로 정의한다. [에이전트 실행 로그 관행](https://dev.to/web4browser/what-ai-browser-agents-should-log-after-every-run-ikg)은 자신감 있는 요약 대신 증거를 기록하라고 한다. 세 출처의 필드가 이 repo의 기존 기록 필드와 겹치므로, 새 개념이 아니라 기존 기록의 작업 단위 결집으로 채택했다. 회의록이 이해도와 속도를 개선한다는 효과 주장은 파일럿 측정 전까지 하지 않는다.
