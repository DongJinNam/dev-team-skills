# 보고서 결론과 3문장 요약 계약

상황을 분석해 결론을 내리는 보고서(검증·비교·의사결정·완료 보고)를 작성하거나 요약할 때 적용한다. 보고서 첫머리의 요약과 별도로 제공하는 최종 요약은 각각 **무엇을 → 어떻게 → 왜, 정확히 3개의 완결된 문장**으로 작성한다. 본문과 증거 표에는 문장 수 제한을 적용하지 않는다. 일반 대화·단순 진행 알림·홍보 문구 전체를 이 형식으로 바꾸지 않는다.

## 1. 요약 전에 시나리오 정리

핵심 주장별로 `판단할 질문 | 확인된 사실·출처·기준일 | 가정·미확인 | 판정 | 다음 조치·재판단 조건`을 정리한다. 사실 확인, 가치 판단, 향후 효과 예측을 분리한다. 일부 근거의 타당성이 주장 전체나 미래 효과를 입증하지는 않는다. 투표는 권고안을 선택할 수 있지만 사실을 입증하는 증거는 아니다.

| 근거 상태 | 판정 및 요약에 남길 내용 |
| :--- | :--- |
| 질문의 범위 전체를 충분한 근거가 지지함 | 해당 범위에서 지지한다고 명시하고 유지·실행할 조치와 핵심 근거를 제시한다. |
| 일부만 지지하거나 특정 조건에서만 성립함 | 지지되는 부분과 미확인 부분을 나누고 조건부 권고·추가 확인 방법을 제시한다. |
| 신뢰할 수 있는 근거가 주장을 반박함 | 해당 주장을 기각하고 정정·대체 조치와 반박 근거를 제시한다. |
| 근거끼리 충돌함 | 쟁점과 출처의 직접성·시점·방법 차이를 비교하고 판정 가능한 범위 및 충돌 해소 방법을 제시한다. |
| 판단에 필요한 자료가 없음 | 판단 보류를 명시하고 필요한 자료·확인 방법·재판단 조건을 제시한다. 자료 부재를 거짓의 증거로 쓰지 않는다. |

여러 시나리오가 있으면 현재 근거가 지지하는 기본안과 이를 바꾸는 관찰 가능한 조건을 구분한다. 확률·효과 수치·담당자·기한을 지어내지 않는다. 권고와 이미 실행한 조치를 구분한다.

## 2. 필수 3문장

1. **무엇을 — 판정:** 질문에 직접 답하고 채택·조건부 채택·기각·판단 보류 중 적합한 결론 또는 동등한 명확한 표현을 쓴다; 적용 범위와 결론을 좌우하는 조건을 함께 남긴다.
2. **어떻게 — 조치:** 그 판단에 따라 누가 무엇을 실행하거나 어떤 자료를 어떤 방법으로 확인할지 쓴다; 보류·조건부 판단이면 재판단 조건을 명시하며 정해지지 않은 담당자·기한을 만들지 않는다.
3. **왜 — 근거:** 결론을 지지하는 핵심 증거와 그 한계를 연결해 쓴다; 본문의 출처·증거 식별자로 추적할 수 있게 한다.

세 항목을 한 문장에 몰아넣거나 제목·명사 나열만으로 세 문장을 대신하지 않는다. “맞는 근거이지만 확실하지 않다”에서 끝내지 말고 무엇이 확인됐고 무엇이 미확인인지 특정한다. 명료함을 위해 불확실성을 삭제하거나 근거보다 강하게 단정하지 않는다. 긴 출처·보조 설명은 본문으로 옮기되 판정을 바꾸는 조건·위험·미검증 상태는 요약에도 남긴다.

## 3. 편집 순서와 검수

Lead가 시나리오별 사실·판정을 확정한 뒤 Ponytail은 중복만 축약하고 세 문장의 판정·조치·근거를 보존한다. Humanizer Editor는 쉬운 표현으로 바꾼 뒤 원문과 대조하여 3문장 구조, 수치·부정·조건·위험·출처·미확인 상태를 다시 확인한다. 새 사실이나 새로운 권고가 필요하면 Lead에게 돌려보내며 편집자가 임의로 결론을 바꾸지 않는다.

QA/Test Engineer(작은 작업은 Lead 겸임)는 아래 조건을 모두 확인한다.
- 정확히 3문장이며 순서대로 무엇을·어떻게·왜에 답한다.
- 첫 문장만 읽어도 판단 대상과 결론을 알 수 있고 둘째 문장에 실행 또는 확인 방법이 있다.
- 셋째 문장의 근거가 본문 증거와 일치하며 요약 전후 사실 변경·핵심 조건 누락이 0건이다.
- 자료 부족·부분 지지·반박·충돌 시나리오에서 근거 없는 확신 또는 근거 없는 양비론이 없다.
- 보안 보고의 PASS/BLOCKED 등 기존 판정과 필수 보고 필드는 본문에 그대로 보존한다; 3문장 요약은 검수·투표·승인 게이트를 대체하지 않는다.

## 4. 예시: 근거 일부만 확인된 경우

다음은 형식 설명용 가상 사례이며 실제 측정 결과가 아니다.

입력: 캐시 적용으로 API 지연이 30% 감소한다는 제안, 단일 테스트 200ms → 140ms(증거 T1), 운영 부하·오류율 미측정.

> 캐시의 지연 감소 효과는 단일 테스트에서 확인됐지만 운영 적용 판단은 보류합니다.
> 운영과 유사한 부하에서 지연과 오류율을 측정한 뒤 사전에 합의한 통과 기준 충족 여부로 적용을 재판단합니다.
> 테스트 T1에서는 지연이 200ms에서 140ms로 30% 줄었으나 운영 부하와 오류율은 아직 검증하지 않았기 때문입니다.
