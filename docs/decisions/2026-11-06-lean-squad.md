# 역할 구조조정과 외부 활용 점검

## 판정 요약

기존 15개 역할명을 6개 책임 역할로 통합하고 외부 도구의 활용 증거를 기록하는 안을 채택한다.
작업 크기에 따라 담당을 배정하고 기존 시작·중단·품질·독립 보안·컴플라이언스 게이트를 유지하며 행동 평가로 확인한다.
기존에도 선택 호출은 가능했지만 역할과 중복 문서가 분산되어 있었고 외부 참고 목록만으로 실제 활용 성과를 증명할 수 없었기 때문이다.

## 무엇이 확인되었나

점검 기준은 fetched main `8fd545f`이며 PR #17의 사용량 비교기를 포함한다. 역할명은 전문 14개+Lead 1개, Tier 1/2 결정 책임자는 8개였다. 이 둘은 같은 지표가 아니다. 실제 실행 로그 전체를 확보하지 않았으므로 과거에 모든 역할을 호출했다거나 토큰을 낭비했다고 단정하지 않는다.

| 항목 | 점검 결과 | 조치 |
| --- | --- | --- |
| QA/Test | 기준 설계와 실행/회귀 인계가 두 역할에 분산 | Quality가 한 AC-테스트-증거 기록 소유 |
| DevOps/SRE | 배포와 복구·관측 소유권 분산 | Delivery 통합; 기존 서비스 설정 변경도 활성화 |
| Planner/Marketing/Rookie | 제품 판단·메시지·반론이 각각 역할 | Product 통합, 반론은 제안자 외 활성 담당에게 배정 |
| Finance/Humanizer | 별도 관점이 작은 작업에도 인계로 해석될 여지 | Lead의 비용/설명 업무로 명시 |
| Security/Compliance | 별도 역할을 유지하는 비용과 전문성 문제 | 독립 Security가 적용성 조정; 별도 준수 판정·미해결 위반 차단·전문 검토 유지 |
| 구 경로 사본 | `skills/SKILL*`, `skills/references/roles*`에 다른 본문 | 정본 연결로 전환; 배포 계약도 동일 처리 |
| 외부 자료 | 기존 목록 자체가 설치·실행 미검증이라고 명시 | 활용 상태·대상·명령/산출물·AC·검토·한계 기록 |

## 토론과 결정

대안은 기존 14개 전문 역할 유지, 6개 책임 역할 통합, Lead/개발/검수 3개로 축소였다. [설계·토론안](../superpowers/specs/2026-11-06-lean-squad-design.md)에 장단점을 비교했다. 구현자(root)가 6개안을 제안했고 실제 독립 검토자 `/root/design_review`가 반론했다. 가상의 다수결은 하지 않았다.

가장 강한 반론은 “이미 선택 호출인데 직함만 줄이는 것이 무슨 효과인가”였다. 호출 절감을 실측 성과로 쓰지 않고, 책임 단일화·작은 작업 경로·중복 문서 제거를 검증 대상으로 바꾸었다. Lead의 자기 보안 승인 금지, 컴플라이언스 별도 차단, 역할별 역량과 증거 누락 방지, 기존 서비스의 운영 변경 경로를 함께 반영했다.

## 최근 자료와 실제 활용의 차이

2026-11-06 KST 공식 원문 확인: [Superpowers](https://github.com/obra/superpowers) 약 313.1k stars, [Anthropic skills](https://github.com/anthropics/skills) 약 187.8k, [Playwright CLI](https://github.com/microsoft/playwright-cli) 약 15.0k, [Agent Skills](https://github.com/agentskills/agentskills) 약 27.0k. 이는 웹 표시의 관심도이며 실사용률·최근 성장률·품질 순위가 아니다. 과거 시점의 동일 조건 지표가 없어 “최근 급증”은 판정하지 않았다.

| 후보 | 이 작업의 관찰 상태 | 실제 채택/보류 근거 |
| --- | --- | --- |

## 검증 기록과 한계

- 사전 정책 적용: `/root/baseline_routing`은 작은 PR·복합 변경·외부 후보·Superpowers 재사용 4가지에서 기존 필수 게이트를 보존했다. 작은 작업 경로는 해석이 필요하다고 보고했다. 실패율이나 모델 간 비교 자료가 아니다.
- 본문 길이: 한국어 SKILL 116→55줄, roles 342→66줄; 영어 SKILL 118→55줄, roles 342→66줄. 실제 토큰 수와 다르다.
- 신규 5개 상황: 작은 문서 변경, 기존 서비스의 배포/마이그레이션, 미실행 외부 도구, 실패한 도구 실험, 보안 PASS와 별개의 준수 위반. 기존 14개와 합쳐 19개.
- 채점기 회귀: 새 동작 식별자/정책 연결 전 7개 테스트 실패를 확인한 뒤 최소 변경으로 통과시켰다. 전체 단위 테스트 63개와 패키지 Bash 하네스 통과. 합성 fixture는 실제 에이전트 증거가 아니다.
- 첫 에이전트 응답은 구조 채점 13/19, 독립 의미 검토 19/19였다. 보안 증거 상태와 실행 차단 상태, 설명문의 조치와 action 목록, 채택 거절과 채택 가능 여부의 표기 차이를 확인했다. 원본은 `evals/runs/2026-11-06-lean-squad-initial.json`에 보존한다. 공개 응답 계약과 도구 채택 질문의 판정 대상을 명확히 한 뒤 기대 답안을 보지 않은 새 actor로 재평가했다. 정책이나 차단 기준을 느슨하게 바꾸지 않았다. 새 actor는 처음 18/19 구조 검사를 통과했다. 남은 컴플라이언스 사례는 시작하지 않은 머지를 BLOCKED로 판정했는데도 `stop` 식별자까지 요구하던 중복 채점 조건이었다. 독립 의미 검토 의견에 따라 그 required action만 제거하고 같은 원본 응답을 재채점했다. BLOCKED 판정·별도 compliance BLOCKED·위반 기록·merge/override_security 금지는 유지하며 READY·준수 PASS/누락·merge를 거부하는 회귀 테스트를 추가했다. 원점수·당시 snapshot과 재채점 이유는 최종 기록에 남겼으며 이를 새 모델 실행으로 표시하지 않는다.
- 독립 검토의 첫 단위 테스트에서는 19개 어댑터 하위 프로세스를 포함한 한 테스트가 20초 제한을 넘었으나 평가 테스트 18개 재실행은 3.863초에 통과했다. 원 작성자의 전체 59개 테스트도 통과했으며 재현되지 않은 지연을 숨기지 않고 기록한다.
- 최종 구조 채점·독립 의미 검토 모두 19/19 통과했다. 실제 행동 응답과 별도 의미 검토는 `evals/runs/2026-11-06-lean-squad.json`으로 관리한다. 한 actor 문맥의 19개 판단이며 19회 독립 표본·실제 도구 실행·품질 확률을 증명하지 않는다.
- 로컬 PowerShell은 미설치로 NOT_RUN. Windows/macOS와 PowerShell 결과는 PR의 3 OS × 2 launcher CI에서 별도로 확인한다.
- 실제 토큰/시간/비용 절감은 UNMEASURED. PR #17의 `evals/compare_usage.py`에 동일 모델·작업·품질 조건의 전체 사용량 로그를 넣어야 수치화할 수 있다.

이번 변경은 후보의 활용을 확인하는 절차와 스킬 구조를 개선한 것이다. 새로운 외부 CLI 실행 성공, 사용자 만족도 향상, GitHub 머지 버튼의 자동 잠금은 검증 범위가 아니다. PR은 검토 대상으로 생성하며 자동 머지하지 않는다.

## PR CI에서 확인한 실제 실행 경로

첫 원격 CI는 Linux/macOS의 두 셸 모두 통과했고 Windows 두 셸에서 신규 테스트의 기본 cp1252 디코딩이 실패했다. 한국어 정책 JSON을 읽는 테스트에 UTF-8을 명시했다.

[자동 리뷰 봇의 실제 출력](https://github.com/DongJinNam/dev-team-skills/pull/18#issuecomment-6679271171)은 모델 응답을 확보하지 못한 안내에서 예전 8인 역할과 하네스 통과 문구를 출력했다. 스크립트는 하네스 명령을 실행하지 않으므로 이 문구는 사용/검증 증거가 아니었다. 현재 역할 매핑을 읽도록 연결하고, 응답 없는 fallback은 AI 검토·하네스·독립 보안을 NOT_RUN으로 보고하도록 고쳤다. 제공자·인증·외부 전송 경로는 바꾸지 않았고 실제 모델 호출 성공을 주장하지 않는다. 두 오프라인 회귀 테스트의 실패를 확인한 후 수정했다. 독립 검토자가 추가 diff를 다시 확인하며 최종 CI/보안 상태는 PR에 기록한다.
