# 작업 회의록(Work Minutes) 도입 결정 기록

> 기준: dev-team-skills main `bd5e080` (2026-11-11 확인). 요청: 사용자 (2026-11-11) — 일을 맡겨두면 역할마다 무엇을 했고 왜 그렇게 했는지 알 수 없어, 회의록 같은 기록을 남기고 싶다. 사람과 AI 에이전트가 빠르고 효율적으로 이해할 수 있는 회의록이 주제다.

## 무엇을

작업 종료·중단 시 작업 1건당 회의록 1건을 남기는 계약을 engineering-squad에 추가한다. 회의록은 작업 대상 repo의 `docs/worklogs/`에 둔다. 상단은 기존 3문장 요약 계약을 재사용하고, 본문은 메타·역할별 기록 표·결정 색인·검증 요약·비용·미해결/다음으로 고정한다.

## 어떻게

- 신규 참조: `skills/engineering-squad/references/work-minutes.md`와 영문판 `work-minutes_en.md`
- `.agents/skills` 미러를 같은 내용으로 갱신한다 (MIR-001)
- SKILL.md 실행 단계 연결(6단계 "기록" 추가와 비용 절 인계 연결)은 이 PR에서 분리한다. SKILL.md가 eval 캡처 snapshot에 묶여 있어, SKILL.md를 바꾸면 기존 캡처가 STALE이 되어 CI 재생이 실패하는 것을 PR #30에서 확인했다. 연결은 캡처 갱신과 함께 후속 PR로 미룬다
- 효과 검증은 기존 19개 압력 시나리오에 넣지 않고, 실제 작업 3건 파일럿으로 분리해 보충 기록으로 남긴다. 보충 사례를 본점수에 넣지 않는 기존 관행을 따른다

## 왜

현재 기록 장치는 흩어져 있다. 시작·중단 합의는 roles.md에, 결정 기록은 decision-governance.md §5에, 검증 기록과 비용 기록은 SKILL.md의 단계 설명에 있다. 그런데 §5가 전제한 "기존 작업 기록"의 형식과 위치가 정의돼 있지 않고, 작업이 끝난 뒤 역할별 수행과 이유를 한곳에서 볼 문서가 없다. 회의록은 이 빈칸만 채운다. 기존 기록의 본문을 복제하지 않고 링크로 묶으므로 기록이 어긋날 지점이 늘지 않는다.

외부 근거 (2026-11-11 확인): HANDOFF.md 인계 관행, SYNTAX Methods Note v1.0의 세션 로그, 에이전트 실행 로그 관행 3개의 필드 구성이 이 repo의 기존 기록 필드와 겹친다. 새 개념 도입이 아니라 기존 기록의 작업 단위 결집이다. 출처와 대조 전문은 work-minutes.md §6에 있다.

## 대안과 기각 이유

- 회의록 없이 PR 설명으로 대체: PR이 없는 작업(조사·문서·운영)에는 남지 않고, 역할별 행 구조가 없어 기각했다.
- 대화 전문이나 실행 로그를 그대로 보존: 읽는 비용이 크고 컨텍스트 팽창을 부른다. 기존 인계 원칙(결정·근거·미해결·필요 파일만)과 충돌해 기각했다.
- 결정 기록(docs/decisions/)에 작업 기록까지 통합: 결정은 안건 단위, 회의록은 작업 단위라 수명이 다르다. 섞으면 둘 다 찾기 어려워져 기각했다.

## 한계와 재판단 조건

효과 실측은 없다. 회의록이 이해를 돕는다는 것은 가설이다. 실제 작업 3건에 적용한 뒤 아래를 기록해 유지·축소·폐기를 재판단한다.

- 사용자가 회의록만으로 이해했는가 (재질문 발생 여부)
- 작성 비용 (줄 수, Lead 비용 기록의 실측/추정)
- 제3의 에이전트가 회의록만으로 미해결과 재개 조건을 답할 수 있는가

형식 채우기로 변해 작성 비용이 이해 이득을 넘으면 약식 범위를 넓히거나 폐기한다.
