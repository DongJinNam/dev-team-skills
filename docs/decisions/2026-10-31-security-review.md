# QA 필수 보안 검수 역할 결정

## 요구사항과 변경 범위

사용자 요청: 보안 엔지니어를 dev team에 추가하고 QA 단계에서 필수화한다. 기획·마케팅이 공개 스킬과 최근 개인정보 사고를 조사하고 PR 전에 내부 토론으로 방식을 합의한다.

최신 `origin/main`의 기획·마케팅·재무 역할을 유지하며 11번째 전문 역할 Security Review Engineer를 추가한다. 구현자와 별도 검토자를 두고 Stage 3의 QA PASS + security PASS를 Stage 4 진입 조건으로 삼는다. 기존 게이트 번호를 보존하기 위해 Gate 3a를 추가해 총 8개 게이트로 만든다.

변경 대상: engineering-squad 본문/역할/배포 게이트, code-review 체크리스트·심각도 기준, 루트 스킬 미러, 한영 README와 4개 marketplace/plugin manifest. 새 자료는 보안 검수 계약과 날짜가 있는 조사 근거로 분리한다. 외부 스킬 설치·코드 복사·실행 의존성·서비스 실행 코드·CI 차단 자동화는 추가하지 않는다.

## 내부 토론과 결정

| 관점 | 제안 또는 반론 | 결정 |
| :--- | :--- | :--- |
| 기획·마케팅 | 조사 후보 중 채택 지표가 높은 스킬의 역량 조합. 인기는 안전성·효과 입증이 아니다. | Sentry security-review + Trail of Bits differential-review/insecure-defaults의 관점을 자체 절차로 조합하고 출처·날짜·한계를 기록한다. 전체 시장 최상위 주장과 자동 설치는 하지 않는다. |
| 기획·보안 | Sentry 원문의 인증 경로 제외가 권한 침해 누락 가능성을 만든다. | 해당 제외 규칙을 거부한다. 로그인한 사용자 간 객체 소유권·테넌트 격리도 필수다. |
| QA | 기존에는 필수 보안 역할·판정·증거 계약이 없다. 기능 QA와 독립 판정이 필요하다. | 필수 별도 리뷰어, 리비전별 보고서, 미검증/개인정보 노출 의심 차단과 변경 후 재검수를 도입한다. |
| QA | 스캐너 NOT_RUN 일괄 차단과 동등 수동 검증 허용이 모호하다. | 도구 실행 NOT_RUN 로그는 보존한다. 동등 검증의 충분성을 독립 검토자가 확인하면 검사 영역을 PASS로 판정한다. |
| 보안 리뷰 | Medium/Low 위험 수용과 검사 FAIL·기존 Must Fix 규칙이 충돌할 수 있다. | 검사 상태와 finding 처리 상태를 분리한다. 수정·근거 있는 오탐·명시적 위험 수용 이후에만 영역 PASS. 한영 code-review rubric도 같은 계약에 연결한다. Critical/High·노출 의심·증거 공백은 수용으로 면제하지 않는다. |
| Lead의 비용 검토 | 모든 역할 호출·무한 토론은 비용을 늘린다. | 기획/마케팅 1명, QA 1명, 독립 보안 리뷰어 1명으로 범위를 제한하고 반론을 수정에 반영한다. 필수 보안 검수는 비용 절감으로 생략하지 않는다. 토큰·청구액 계측은 없어 금액을 추정하지 않는다. |

외부 전문 지침은 참고 자료이며 자체 계약이 우선한다. 개인정보 사고에서 검수 범위를 도출한 것은 설계 판단이며 특정 스킬이 사고를 예방했을 것이라는 주장은 하지 않는다.

## 동작 검증

변경 전 QA 검토에서 명시적 필수 보안 역할·보안 게이트·PASS/BLOCKED 계약 부재를 확인했다. 변경 후 QA가 다음 시나리오를 지침에 적용했다.

| 시나리오 | 판정 |
| :--- | :--- |
| E2E 통과·마감 압박·스캐너 불가·개인정보 로그 노출 의심 | BLOCKED, 기능 QA로 대체 불가 |
| 로그인 사용자가 다른 테넌트 청구서 조회 | BLOCKED, 인가 경계 수정·재검수 |
| 문서 한 줄이라는 이유로 외부 명령도 N/A 처리 | BLOCKED, 실제 실행/반출/권한 경로 검토 필요 |
| PASS 이후 lockfile 변경 | 이전 PASS 무효, 새 리비전 영향 검수 필요 |
| 스캐너 불가지만 동등 수동 검증 증거 충실 | 독립 검토자의 충분성 확인 및 다른 차단 사유 부재 시 보안 PASS 가능 |

기존 Bash 하네스, JSON 파싱, 변경 Markdown 상대링크, 루트/하위 스킬 참조 정합성, diff 공백 검사를 실행한다. 서비스 코드가 없는 지침 변경이므로 컨테이너·런타임 헬스체크는 해당하지 않는다. 에이전트 시나리오 검토는 행동 검증이며 실제 애플리케이션 취약점 스캔이나 CI 보안 차단 구현을 뜻하지 않는다.

## 추가 요구사항: 최신 보안 이슈 확인

매 검수·배포 직전 공식 권고와 실제 악용 이슈를 확인하고 출처·갱신일·확인일·영향 버전·적용 여부·대응을 보고서에 기록한다. 최신 정보 접근이 불가하면 공백을 밝히고 적용 위험을 평가할 수 없으면 차단한다. 자동 상시 감시는 별도로 구축하지 않았으므로 수행 중이라고 주장하지 않는다.

## 한계

필수 검수는 에이전트 실행 계약이다. 저장소 branch protection이나 CI의 기계적 승인 차단을 설정하지 않는다. 보안 PASS도 무취약점 또는 법적 인증을 의미하지 않는다. 별도 검토자나 동등한 검증 증거를 확보하지 못하면 작업은 BLOCKED 상태로 보고한다.
