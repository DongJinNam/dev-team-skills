# 실측 개선안의 스킬 반영

설치·인코딩 실패와 비교 지표의 해석 한계를 현재 스킬의 한국어·영어 지침에 반영했다.
Engineering Squad의 읽기·증거 계약과 Harness Engineering의 발견·실행·공개 절차를 수정하고 현재 정책에 맞는 판단 회귀 증거를 별도로 수집했다.
기존 12회 비교는 제한된 관측이므로 원본을 보존하며, 이번 지침 검증을 새로운 성능 향상이나 Claude 호환성 입증으로 해석하지 않는다.

## 범위와 실제 토론

사용자는 개선안을 현재 스킬에 반영하고 commit/push/PR까지 진행하도록 요청했다. 일시 중단 뒤 “이어서 진행시켜”로 재개했다. [계획](../superpowers/plans/2026-11-08-skill-feedback.md)을 따르며 Lead가 구현·품질·최종 설명을 겸임하고 별도 담당자가 의미·보안을 검토한다. COMBINED 모드이며 기존 합의와 승인된 작업 범위를 재사용한다. 추가 CLI 성능 비교·별도 API 결제·머지·배포는 실행하지 않는다.

`/root/eval_review`는 기존 19개 검사만으로 새 인코딩·비교 지침까지 검증했다고 하면 과장이라고 반론했다. 이를 수용해 19개는 기존 판단 계약 보존, 새 3개는 새 지침의 정성 판단 검사, Codex 조회는 실제 발견 검사로 나눴다. 별도 subprocess를 sandbox라고 부르면 안 된다는 반론도 반영해 실제 파일·네트워크 통제와 잔여 노출을 명시했다. 영어의 “작은 차이”를 “작은 표본에서 관측한 차이”로 바로잡고, 인증 파일·비공개 추론은 마스킹 공개가 아닌 제외 대상으로 구분했다.

## 변경과 검증 경계

| 변경 | 확인 방법 | 증명하지 않는 것 |
| --- | --- | --- |
| UTF-8 명시 읽기, 깨진 정책 재읽기, 설치·발견·적용 분리 | 양언어 검토, 새 인코딩/발견 상황 판단, 실제 native 발견 조회 | 모든 OS·호스트 호환성 |
| 고정 비교 조건·실패 분모·사후 검사·캐시/전체 사용량 구분 | 양언어 검토와 새 비교 주장 상황 판단 | 일반 우수성·동등성·비열등성·금전 절감 |
| 생성 코드 사전 검토·임시 인증 제거·실제 접근 통제·로그 정제 | 새 실행/공개 상황 판단과 독립 보안 검토 | 미검토 코드의 안전 실행·sandbox 보증 |
| BOM 거부·영어 스킬 검사, 잘못된 설치 안내 수정 | 회귀시험과 앞선 실제 설치·발견 증거 | Claude 실행 성공 |
| 실험 파일의 바이트 보존 | `.gitattributes`로 고정 파일만 `-text`, Git blob과 작업 파일 대조 | 기존 실험의 인코딩/캐시 통제 한계 해소 |

79개 단위 테스트는 모두 통과했다(`HARNESS_LAUNCHER=python`, 46.107초). 테스트 출력의 모델 호출 문구는 mock 기반 테스트이며 외부 모델 호출이 아니다. Windows PowerShell과 Git Bash 패키지 검사, `git diff --check`도 통과했다. 실제 Codex 조회는 고유 스킬 **8/8**, 별칭 포함 엔트리 **9개**, 오류 **0개**, 모델 호출 **0회**였다([발견 증거](../../evals/runs/2026-11-08-codex-discovery.json)). 로컬 macOS/Linux 실행은 NOT_RUN이다.

## 판단 응답의 출처와 준비 실패

새 native actor `/root/skill_regression_actor`는 공통 정책을 한 번 묶어 받은 뒤 기존 19개 공개 질문과 응답 계약에 답했다. 기대 답안·이전 응답·테스트 파일은 제공하지 않았다. [19개 기록](../../evals/runs/2026-11-08-skill-feedback.json)은 응답 JSON 값을 수정하지 않고 가져왔으며, 별도 `/root/eval_review`가 의미와 응답/정책 해시를 검토한다. CI의 재검사 대상만 새 기록으로 옮기고 기존 기록은 그대로 보존한다.

같은 actor가 [새 3개 상황](../../evals/runs/2026-11-08-skill-feedback-pressure.json)에도 답했다. 최초 입력은 PowerShell 파이프로 전달한 한글이 `?`로 대체되어 actor가 읽기 불가를 보고했다. 이 입력과 응답을 준비 실패로 보존하고 유효 사례 점수에 넣지 않았다. UTF-8로 파일을 다시 만든 뒤 답안 힌트 없이 같은 질문을 제공했다. JSON 응답 파일의 BOM은 JSON 읽기에서 처리했으며 응답 값은 바꾸지 않았다. 스킬 frontmatter의 BOM 금지와는 별개다.

한 actor 문맥에서 수행한 판단 검사이며 독립 표본 22회나 실제 도구 동작 증거가 아니다. provider 모델 ID·사용량을 별도 계측하지 않았으므로 UNMEASURED다. 신규 3개를 기존 19개 점수나 12회 성능 비교에 합산하지 않는다.

최종 독립 의미 검토는 기존 **19/19 PASS**, 별도 신규 상황 **3/3 PASS**다. 검토자는 응답 값을 수정하지 않고 각 사례의 근거·응답 해시·정책 해시만 기록했다. 현재 정책으로 실행한 재검사도 **19/19 PASS**, `tool_execution=NOT_OBSERVED`다. 초기 입력 준비 실패는 삭제하거나 성공으로 바꾸지 않았다.

## 게시 검토

독립 보안 담당 `/root/security_review`의 예비 검토에서 새로운 보안·컴플라이언스 차단 사유가 없었다. 기존 공개 실험 80개와 고정 소스 해시가 유지됐고 개인정보·시크릿·제삼자 스킬 전문 검사에서도 발견사항이 없었다. 최종 커밋 head/base를 대상으로 갱신한 판정은 PR 본문에 기록한다. 새 head 또는 머지 입력이 바뀌면 재검토가 필요하며 이 문서는 미래 커밋의 승인이 아니다.
