# 외부 저장소 기여 증거와 PR 인계 개선

외부 저장소에 코드와 테스트를 기여할 때 사용하는 증거·인계 양식을 추가한다. 기존 6개 책임 역할을 유지하고, 한·영 참조 문서를 조건부로 연결하며 기존 평가기에 기여 사례 5개를 추가한다. 기여 조건부터 변경 전후 검증, 최종 승인, 게시 내용 확인까지 같은 기록으로 검토할 수 있도록 하기 위해서다.

## 배경과 선택

기준은 `DongJinNam/dev-team-skills`의 `633e36d8dc6ea75956bc86d717bbb5738775b22f`다. [HikariCP #2433](https://github.com/brettwooldridge/HikariCP/pull/2433)을 준비하며 다음 기록이 필요했다.

- 백엔드 코어 개선 요청과 번역 기여를 구분하고, 라이선스 외에 기여 조건을 확인한다.
- 변경 전 회귀 실패, 변경 후 성공, 추가 스트레스 테스트 실패의 기존 코드 대조를 남긴다.
- Docker 테스트 미실행과 실제 PostgreSQL을 사용한 대체 검증을 구분한다. 쿼리 수 감소를 측정하지 않은 지연 시간 개선으로 바꾸지 않는다.
- 신규 파일을 포함한 파일 수와 줄 수, 최종 PR 본문을 승인 대상으로 제시한다.
- connector 쓰기 실패와 허용된 다른 게시 경로를 구분하고, 게시된 파일을 로컬 검증 대상과 대조한다.

새 전담 역할이나 별도 실행 도구를 만들면 기존 Lead/Engineering/Quality/Security와 책임이 겹친다. 일반 계약을 다시 늘리는 대신 외부 기여 작업에서만 참조하는 양식을 선택했다. 실제 API·브라우저 권한 확대나 GitHub 보호 규칙 설정은 포함하지 않는다.

## 검증과 한계

변경 전후 각각 별도 actor 5개에 같은 기여 인계 과제를 주었다. 원본 답변과 입력 과제는 [비교 기록](../../evals/runs/2026-11-07-oss-handoff-samples.json)에 보존한다. 기존 절차도 승인 대기, 실패 공개, 미측정 성능 주장 방지를 처리했다. 소수 정성 표본으로 오류율·토큰 비용·PR 수용률 개선을 주장하지 않는다.

독립 검토에서 모든 후보 답변이 PR 생성 전 원격 내용 대조 순서를 명시했다. 기존 답변 중 하나는 PR을 만든 뒤 비교하는 순서였고, 나머지도 생성 전 전체 내용 대조를 명확히 요구하지 않았다. 후보 5개 중 4개는 과제에 주어지지 않은 PostgreSQL 메서드의 성공 여부도 미확인으로 드러냈다. 이는 이번 원본 답변에서 관찰한 차이이며 실제 게시 성공률을 뜻하지 않는다.

자동 채점기의 합성 fixture와 실제 actor 응답은 별개다. 단위 테스트는 채점기가 잘못된 증거를 거부하는지 확인하며, 실제 게시 도구 실행을 증명하지 않는다. 결정 평가의 replay도 저장된 응답을 다시 채점할 뿐 새 모델 실행이나 GitHub 권한 강제 기능이 아니다.

평가 개발 중 실패도 보존한다. [첫 응답](../../evals/runs/2026-11-07-oss-contribution-initial.json)은 구조 22/24, 의미 검토 23/24였다. 진행 대상이 불명확한 질문과 빠진 기록 행동 항목을 공개 입력에서 명확히 했다. [두 번째 응답](../../evals/runs/2026-11-07-oss-contribution-second.json)은 구조 23/24, 의미 검토 22/24였다. 미정의 상태 어휘 문제는 입력 계약에 명시했고, 검토자 부재와 롤백 검증을 근거 없이 단정한 두 응답은 거부했다. 실패한 원문을 고치거나 통과 기록으로 바꾸지 않았다.

실행한 검증:

- 변경 전: 단위 테스트 63개 통과.
- 회귀 테스트 추가 직후: 새 참조·시나리오 부재를 포함한 9개 하위 검사 실패를 확인했다.
- 변경 후: `python -m unittest discover -s tests -v`, 65개 통과.
- `bash scripts/verify-harness.sh`: 패키지 구조·한영 헌법 동기화 통과.
- `bash evals/run-evals.sh --replay evals/runs/2026-11-07-oss-contribution.json`: 24개 구조 검사와 별도 의미 검토 통과. 최종 수집은 새 actor 3개가 각각 8개 사례를 처리한 결과이며, 24개 독립 세션이 아니다. replay는 저장된 응답을 재채점한다.

이 환경에는 PowerShell이 없어 Windows/macOS/PowerShell 실행은 미검증이다. 기존 3개 OS와 Bash/PowerShell CI 행렬을 유지하며 새 평가 기록 경로만 바꾼다. 공급자 사용량은 수집하지 않았고, 조건부 참조가 토큰을 얼마나 바꾸는지도 측정하지 않았다. 실제 검토·게시·머지는 각각 별도의 결과로 보고한다.
