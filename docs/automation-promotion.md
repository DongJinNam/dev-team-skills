# 자동화 승격 절차 (observe → auto)

새 자동화는 바로 실행 권한을 갖지 않는다. 관찰부터 시작해, 기록이 쌓인 만큼만 권한을 넓힌다.
근거 결정: [오픈소스 3개 분석 기반 반영 결정 기록](decisions/2026-11-08-open-source-adoption.md)의 B3.

## 단계

| 단계 | 자동화가 하는 일 | 사람이 하는 일 |
| :--- | :--- | :--- |
| observe | 관찰하고 보고한다. 코멘트와 리포트 게시까지만 한다 | 보고를 읽고 판단한다 |
| assist | 제안과 초안을 만든다. 실행은 하지 않는다 | 제안을 검토하고 실행 여부를 정한다 |
| auto | 정해진 범위 안에서 자동 실행한다. 범위 밖 입력은 실행하지 않고 넘긴다 | 범위와 기록을 감사하고, 이상이 있으면 강등한다 |

어느 단계에서도 자동화의 판단이 필수 게이트(독립 보안 검수, 컴플라이언스, 사용자 명시 지시)를 면제하지 않는다.

## 승격 조건

한 단계씩만 올린다. 승격은 PR로 제안하고 아래 기록을 근거로 남긴다.

- 관찰 기록: 현재 단계에서 최소 20회 실행 또는 2주 운영. 실행마다 입력, 판단, 실제 결과를 남긴다.
- 정확도: 오탐과 미탐을 셈한다. auto 승격의 기준은 관찰 기간 오탐 0건이다. 기준을 바꾸려면 이 문서를 고치는 PR에 이유를 적는다.
- 가역성: 자동 실행 결과를 되돌릴 수 있어야 한다. 되돌릴 수 없는 동작(외부 발송, 결제, 삭제)은 auto 대상이 아니다.
- 담당자: 자동화마다 책임 담당자 1명을 정한다. 담당자가 없으면 승격하지 않는다.
- 승인: assist 승격은 담당 분야 Tier 2 이상, auto 승격은 사용자가 승인한다.

## 강등과 중단

- 사고 1건, 또는 오탐이 반복되면 즉시 observe로 강등한다. 강등에 별도 승인은 필요 없다.
- 기반 정책이나 계약이 바뀌면 승격은 무효가 된다. 바뀐 정책으로 다시 평가하기 전에는 이전 단계로 돌아간다.
- 강등과 재승격은 날짜와 이유를 이 문서의 현황 표 아래 기록에 남긴다.

## 현재 상태 (2026-11-08)

| 자동화 | 단계 | 근거 |
| :--- | :--- | :--- |
| AI 코드 리뷰 bot | observe | PR에 코멘트만 게시한다. 머지를 막지도, 코드를 고치지도 않는다 |
| verify-harness와 CI 검사 | auto (검사에 한함) | 검사 실패는 머지 게이트를 막는다. 코드를 자동으로 고치지는 않는다 |
| 독립 보안 검수 | 승격 대상 아님 | 자동화가 아니라 head마다 새로 내는 판정이다. 이 절차로 단계를 올리지 않는다 |

## 변경 기록

- 2026-11-08: 절차를 신설했다. 현황 표는 신설 시점의 실제 상태다.
