## 합의와 설계

- 기준: `origin/main` 633e36d, `feature/20261107_codex_update`. 사용자 요청대로 현재 checkout에서 작업한다.
- 사용자 2026-11-07 “동의”: 재안내 없는 적용 성공률, 동일 과제 성공률·시간·전체 토큰을 측정한다. 유료 실행·인증 문제·근거 부족 시 해당 실행/판정을 중단하고 사용자에게 보고한다.
- 목표는 근거 있는 비교다. 우수성이나 목표 개선율을 미리 사실로 정하지 않는다. Claude 미실행은 NOT_RUN이다.
- COMBINED: dev-team이 시작 합의·역할·증거·보안을, Superpowers가 원인 분석·계획·TDD를 담당한다. 같은 범위의 질문·계획을 중복하지 않는다.
- Lead는 구현/품질/설명, `/root/eval_review`는 독립 반론, 최종 별도 검토자는 보안/컴플라이언스를 맡는다. 배포·운영은 범위 밖이다.
- 기존 판단 평가와 토큰 비교기를 유지한다. 설치 전후 실측과 타 스킬 공통 과제 비교는 다른 증거로 기록한다. 타 스킬에는 이 저장소 고유 정책을 정답으로 강제하지 않는다.

## 검토 초점

경로가 plugin root를 벗어나는 입력, 누락 표본을 제외한 성공률 부풀리기, 실패 실행의 시간/토큰 누락, 중복 JSON 키, 기록 집계를 실제 새 모델 실행 또는 우수성 증명으로 표시하는 오류를 검사한다.

실제 모델 비교는 인증/유료 실행 없이 가능한 범위까지만 준비한다. 예제 결과는 fixture이며 실제 성과로 사용하지 않는다. 변경은 로컬에 남기고 push/머지는 하지 않는다.
