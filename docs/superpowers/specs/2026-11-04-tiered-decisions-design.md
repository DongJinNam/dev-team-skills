# 계층별 의사결정 설계

## 목표와 권한
사용자 요청: Claude Code Game Studios처럼 역할을 tier로 나누고, 다수결만으로 결정하지 않는다. 이번 변경 과정에 한해 Tech Lead가 설계·실행을 자율 진행한다. 이 위임을 미래 프로젝트의 자동 승인으로 확대하지 않는다. 기존 프로젝트 시작 질문과 중단 계약은 그대로 유지한다.

기대효과는 책임자 없는 표결 대기와 전문성 없는 과반 결정을 줄이는 것이다. 검증 목표: 기존 14개 역할과 Lead의 tier/보고 경로 누락 0건, 활성 지침의 자동 8표 가결 충돌 0건, 분야 내 결정·분야 충돌·보안 차단·위임 만료·사용자 재검토 사례의 판단 누락 0건. 실제 품질/토큰/시간 개선율은 미측정이다. 중단 기준: 권한 밖 실행, 보안·컴플라이언스 차단 또는 이를 우회해야만 가능한 구현; 사용자에게 현재 대화로 보고하고 명시적 재개를 기다린다. 이 기준은 이번 위임 아래 Tech Lead가 정한 작업 기준이며 사용자에게 직접 답변받았다고 기록하지 않는다.

## 근거와 대안
2026-11-04 확인한 Donchitos/Claude-Code-Game-Studios main `05ad7c8a5b8aa2aa86bbd3439ae7cf7295cac418`의 README, CLAUDE.md, technical-director.md를 참고했다. Director → Department Lead → Specialist, 수직 위임·수평 자문·상위 책임자 충돌 해결을 채택한다. 원본의 매번 파일 쓰기 승인·게임 직군·모델 지정·전체 에이전트 수는 도입하지 않는다. 원문을 복제하지 않고 기존 역할에 맞춰 작성한다.

- 동일 가중치 다수결 유지: 간단하지만 사용자 문제를 해결하지 못함.
- 직급별 가중치 투표: 전문성 반영은 가능하나 책임자·교착·게이트 처리가 여전히 불명확함.
- **채택: tier별 단일 책임자 결정 + 근거·반론 + 독립 게이트**. Tech Lead가 위임 범위에서 선택했다. 다수 의견과 다른 결정에는 근거와 재판단 조건을 기록한다.

## 구조와 경계
Tier 1 Tech Lead는 기존 Squad Lead의 명시적 별칭이다. Tier 2는 기존 Planner, AI Agent, Test, DevOps, FinOps, Security, Compliance에 분야 책임을 부여한다. Tier 3는 Frontend, Backend, Data, QA, SRE, Marketing, Rookie다. 직급은 모델 가격이나 추가 에이전트 호출 수를 의미하지 않는다.

분야 내 가역 결정은 지정 분야 책임자, 공통 계약·다분야 충돌은 Tech Lead, 미위임 목표·예산·권한 및 중단 후 재개는 사용자에게 올린다. Security/Compliance와 필수 검증은 상위 직급도 면제하지 못한다. 의견 수렴은 제안 1회·반론 1회 후 결정하며 증거가 부족하면 PENDING, 필수 게이트가 막히면 BLOCKED다.

15표·8표는 요청 시 참고용 의견 집계로만 남긴다. 사용자의 재검토·재투표 요구는 즉시 수용하고 미실행 후속 작업을 보류한다. 승인된 안 선택과 실행/머지 권한을 별도 기록한다.

## 변경·검증 범위
한/영 정식 스킬·역할·호환성·리뷰 체크리스트와 호환 진입점·README를 갱신한다. 단일 결정 계약을 정식 references에 둔다. 기존 평가의 pending-vote를 새 정책에 맞게 수정하고 새 경계 사례를 추가한다. 이전 평가 기록은 과거 정책 증거로 보존하고 해시를 바꿔 새 PASS로 위장하지 않는다. 새로운 응답을 별도 수집·검토해 CI의 재생 대상을 바꾼다.

## 검증 기록
- 변경 전 별도 검토자가 세 가지 모의 상황을 적용: 허가된 가역적 백엔드 대안 7표는 PENDING, 공통 API 충돌도 전원 표결로 PENDING, 출시 8표는 채택되지만 보안 BLOCKED로 실행 차단. 전자의 책임 결정 부재를 변경 대상으로 확인했다. 이는 정량 성능 비교가 아니다.
- 변경 후 모의 상황 14개를 같은 에이전트 스레드에서 새로 수집하고 다른 검토자가 전체 응답의 의미·근거·권한을 검사했다. 처음에는 공통 응답 형식이 사실 필드명을 명시하지 않아 채점과 불일치했으며, 공통 키/타입을 명시한 후 같은 스레드에서 새 응답을 수집했다. 기대 답안은 후보에게 제공하지 않았다. 사례별 독립 세션·반복 신뢰도 검증은 하지 않았다.
- Python unittest 38개, 패키지 구조·헌법 동기화, 신규 결정 계약 경로, diff 공백 검사를 실행해 통과했다. 기존 두 평가 기록은 수정하지 않고 과거 정책 근거로 남겼다.
- 독립 검토 지적: PR 양식·메타데이터·README 잔존 다수결 규칙, kickoff와 위임 문구 충돌, 평가 수·재생 경로를 수정했다. 미처리 검토 지적 없음. Windows/macOS 실제 실행은 로컬에서 하지 않았으며 기존 CI matrix가 확인한다.
