# 역할 통합과 외부 도구 활용 증거

## 목표와 범위

최신 main `8fd545f`의 14개 전문 역할 + Lead를 6개 책임 역할로 정리한다. 전문 역량을 삭제하지 않고 담당·활성화 조건·산출물을 한 곳에 둔다. 외부 후보의 인지도와 실제 사용 증거를 구분한다. 사용자는 개선안·토론안 도출, 스킬 반영과 PR 생성을 요청했다. 아래 설계 선택과 수치는 구현자의 제안이며 별도 사용자 합의나 실측 성과로 표현하지 않는다. 이번 범위는 PR 생성까지이며 머지·배포·외부 도구 일괄 설치는 포함하지 않는다.

## 현황

- 상위 스킬은 선택적 호출을 허용하지만 6단계 파이프라인은 작업 크기에 따른 생략 조건이 불명확하다.
- QA/Test, DevOps/SRE, Planner/Marketing/Rookie가 산출물을 나눠 갖고 Finance와 설명 역할까지 인계를 추가한다.
- `skills/SKILL*.md`와 `skills/references/roles*.md`는 별도 사본이며 정본과 이미 다르다.
- 외부 레퍼런스는 스스로 설치·실행 미검증임을 밝힌다. Superpowers 협업 계약은 있지만 실제 도입 판단용 상태·증거 형식이 부족하다.
- 사전 읽기 전용 적용 검토(`/root/baseline_routing`)는 기존 보안·재사용 규칙을 올바르게 적용했다. 관찰된 문제는 규칙 위반이 아니라 작은 작업 경로의 해석 부담이다. 단일 검토이며 실패율이나 토큰 효과를 추정할 수 없다.

## 대안과 토론안

| 대안 | 찬성 근거 | 반론 | 판단 |
| --- | --- | --- | --- |
| 14개 역할 유지, 호출만 제한 | 기존 문서 변경 적음 | 중복 소유권·분산된 설명이 남음 | 미채택 |
| 6개 책임 역할 + 필요 시 전문 역량 | 책임 단일화, 검수 독립성 유지, 큰 작업 확장 가능 | 한 사람이 여러 역량을 갖는다고 오인할 수 있음 | 채택; 전문성 부족 시 한정 위임 |
| Lead·개발·검수 3개 역할 | 가장 짧음 | 제품·운영 책임과 품질/보안 독립성 흐려짐 | 미채택 |

논의 질문: QA/Test 통합 시 누락 검증을 누가 소유하는가? 보안·컴플라이언스를 묶어도 차단권이 남는가? 최신 인기 자료를 링크하는 것과 실제 활용의 차이는 무엇인가? 작은 수정에서 줄일 수 있는 단계와 유지할 검증은 무엇인가? 아래 구조를 이 질문에 대한 제안으로 사용하고 독립 검토 결과를 결정 기록에 남긴다. 가상의 역할별 투표나 사용자 승인 기록은 만들지 않는다.

## 구조

1. Tech Lead: 분야 간 결정, 비용·인계 관리, 최종 설명.
2. Product Lead: 기획·시장 근거·마케팅·반론 실험.
3. Engineering Lead: 구현 책임; FE/BE/Data/AI harness는 작업별 역량.
4. Quality Lead: AC·테스트 설계·실행/회귀 증거의 단일 책임.
5. Delivery Lead: DevOps·SRE·배포·복구·관측.
6. Security Review Engineer: 구현자/Lead와 독립된 보안 판정; 컴플라이언스 적용성 검토와 필요 시 전문 검토 인계.

작은 수정은 Lead 겸임 + 독립 보안 검토자, 일반 기능은 Lead·개발·품질·보안, 서비스 출시는 제품·운영을 추가한다. 이는 호출 수 목표가 아닌 책임 배정 기준이다. Tier 1/2 결정 체계와 Tier 3 위임은 유지하며 별도 직함을 새 에이전트로 해석하지 않는다. 반론 담당은 중요한 결정마다 제안자와 다른 활성 담당에게 배정한다.

기존 시작 질문·중단 계약·사용자 이의·독립 보안·적용 컴플라이언스·배포 게이트는 유지한다. 외부 도구는 DISCOVERED, INSPECTED, AVAILABLE, APPLIED, VERIFIED와 결과 PASS/FAIL/NOT_RUN을 구분하고 대상·실행/산출물 증거로 한정한다. 설치가 검증을 뜻하지 않는다. 공식 출처·확인일·버전·권리·플랫폼·비용·비교 대안과 소규모 검증 결과를 기록한다.

## 검증과 재판단

- 역할명 15 → 책임 역할 6; 기존 Tier 1/2 결정 책임자 8 → 6, 기존 14개 전문 역량의 책임 누락 0.
- 기본 SKILL 본문 100줄 이내; 구 경로는 정본으로 안내하여 문서 사본 제거.
- 작은 작업, 다분야 변경, 미설치 외부 후보, 기존 설계 재사용을 포함한 행동 회귀와 독립 의미 검토.
- 기존 테스트 전체·패키지 하네스·영문/국문·링크 검증, Bash와 사용 가능한 PowerShell, 3개 OS CI 결과를 구분.
- 실제 모델 토큰/시간 절감은 동일 작업·모델·품질 조건의 사용량 로그가 없으면 UNMEASURED. 문서 길이와 책임 수 감소는 토큰 감소율이 아니다.
- 필수 검증 실패·책임 누락·검토자 독립성 상실 시 수정하고 재검증한다. 범위 밖 권한이나 해결 불가능한 차단은 사용자에게 보고한다.

## 구현 순서

정본 스킬·역할·Tier/외부 활용 계약 → 호환 경로·README·manifest·리뷰 참조 → 시나리오·기록·CI → 전체 검증·독립 보안/품질 검토 → commit/push/PR. 되돌리기는 이 PR의 변경을 revert하며 과거 평가 기록은 그대로 보존한다.

## 독립 반론과 반영

`/root/design_review`는 기존에도 선택 호출이 가능하므로 “직함 축소=호출/비용 감소”가 아니라는 반론을 제출했다. 이를 수용해 역할명 15→6과 Tier 결정 책임자 8→6을 분리했고 실측 성과는 UNMEASURED로 남긴다. 보안의 Lead 겸임 금지, 컴플라이언스 별도 차단, 전문 역량/증거 매핑, 기존 서비스의 운영 변경에도 Delivery 활성화를 요구한 의견을 반영했다. 이 기록은 실제 한 명의 독립 검토 의견이며 6개 역할의 투표 결과가 아니다.
